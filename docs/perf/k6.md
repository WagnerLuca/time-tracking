# k6 load test — 2026-10-19

All five scenarios of `loadtest/scenarios.js` (defaults: `USERS=100`, `DURATION=15m`, `BROWSE_RATE=30`, month_end after
5 min) against a production-like stack on the developer machine, after Phases 0–2b.

## Setup

- **Stack**: the backend image built from the working tree (`docker build backend`, Production environment), PostgreSQL
  16-alpine, Mailpit as SMTP — `docker-compose.production.yml`'s `db` + `backend` settings (app connects as the
  non-superuser role created by the same init script, so RLS applies; memory limits 512 MB backend / 1 GB Postgres),
  backend on `127.0.0.1:7100` as in `docker-compose.test.yml`. Not the compose files themselves: the local Docker
  Compose 2.17 cannot parse `docker-compose.production.yml` (nested `${A:-…${B}}` defaults, inline `configs.content` needs
  2.23+), so an equivalent scratch compose file was used (throwaway secrets, deleted afterwards). No Caddy, no frontend,
  no Seq (k6 talks to the backend port directly).
- Overrides for the run, as `loadtest/README.md` recommends: `RateLimiting__AuthStrictPerMinute=500`,
  `JwtSettings__AccessTokenExpiryMinutes=60`, k6 `LOGINS_PER_MINUTE=150`.
- **Data**: `perf-seed --employees 100 --years 10 --core-hours off --force` (22 s: 252,667 time entries, 32,912 absence
  days, 10,943 requests, 105,201 notifications, 29,274 terminal punches). The backend's pre-warm
  (`BalanceCheckpointWarmupService`) computed the org's checkpoints about a minute after start, during k6's `setup()`.
- **Load generator**: `docker run grafana/k6 run` on the same machine (Docker Desktop, Windows 11), `BASE_URL=http://host.docker.internal:7100`.
  Load generator, API and database share one desktop CPU — absolute numbers are pessimistic for latency under CPU
  contention and say nothing about a bigger installation; repeat on the test host before relying on them.

Throughput is set by the scenarios (≈ 12 requests/s, the realistic load of a 100-person organization), not pushed to
saturation; this run shows that a day in such an organization with 10 years of history keeps every interactive call far
below the target. Baseline (Phase 0) was not load-tested with k6, so there is no before column; the per-call before/after
is in `final.md`.
